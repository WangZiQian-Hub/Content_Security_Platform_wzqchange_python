# 模型微调：动机说明与实验方案

> 适用模块：模型训推（模型训练 / 模型管理 / 模型评估 / 模型部署 / 模型调用）
> 这份文档只回答三个问题：**为什么要微调、用哪份数据微调、怎么证明微调有效。**
> 写法尽量用大白话，专业词第一次出现时都给解释。

---

## 0. 一页纸结论

1. **微调 = 给已经"毕业"的模型做岗前培训。** 它不会让模型变聪明，只会让模型更像你要的样子。
2. **微调的教材不是文章，是"一问一答的示范"。** 本项目里能当微调教材的是《模型问答集》，不是《语料集》。
3. **"干净数据"只能防止模型学坏，不能教会模型守规矩。** 想让模型学会拒绝，必须专门喂"坏问题 + 正确拒绝"的示范。
4. **本平台的动机不应该是"让模型具备某领域能力"**（太普通，也不是本平台的职责）。应该是：
   **用同一个底座模型、同一批数据，治理前和治理后各训一次，用同一张考卷对照，用分数差证明数据治理的价值。**
5. **微调不是每天都要真跑的动作。** 《测试平台实施思路》已把"模型训练过程"列为 C 类（可先模拟）。但至少真跑通一次，并留下可追溯的对照证据——否则"治理有效"这句话没有证据。

## 1. 微调到底是什么（大白话）

### 1.1 一个模型是被分三段教出来的

| 阶段         | 大白话       | 喂进去什么                 | 学会了什么                     |
| ------------ | ------------ | -------------------------- | ------------------------------ |
| 预训练       | 读万卷书     | 海量文章（万亿字级）       | 会说话、有常识、懂语法         |
| 微调         | 岗前培训     | 几百到几万条"示范"         | 知道"在我们这儿，该怎么答"     |
| 偏好对齐     | 老师打分纠偏 | 同一问题的"好答案/坏答案"  | 脾气更稳、更守规矩（可选步骤） |

### 1.2 三条必须记住的常识

- **微调不增加知识总量。** 想让它"知道新东西"，先考虑 RAG（检索增强：把资料塞进提示词，让它查着答），便宜、更新快、不用训练。
- **微调改的是"表达方式"。** 口吻、格式、专业说法、遇到某类问题的处理方式——这些查资料解决不了，只能靠微调。
- **数据太少等于没训。** 几十条数据效果看不出来，还可能让它把答案死记硬背（过拟合：只会背题，换一道就不会）。

## 2. 教材：文章和问答是两种东西

打个比方：**预训练是让孩子读书；微调是拿"考卷 + 标准答案"给他看，让他照着学怎么答题。** 这两件事用的材料不一样。

本项目三个数据文件在训练链条里的位置：

| 文件                     | 形状                             | 在链条里的位置           | 能不能当微调教材                                     |
| ------------------------ | -------------------------------- | ------------------------ | ---------------------------------------------------- |
| `语料集_corpus.csv`      | 文章（标题 + 正文 + 来源 + 时间） | 预训练 / 继续预训练      | **不是**微调教材。可作为领域语料做"继续预训练"        |
| `模型问答集_qa.csv`      | 问题 + 模型输出 + 标准答案 + 出处 | 微调（SFT）/ 评估        | **是**。但答案必须用"标准答案"列，不能用"模型输出"列  |
| `反例库_adversarial.csv` | 带异常的条目                     | 数据治理的测试素材       | **不是**教材。是"清洗前 vs 清洗后"对照实验的原料      |

> 注意：`模型问答集_qa.csv` 里的 `model_output`（模型当时答的）本身就带毛病——有啰嗦的、有把同一句话重复 12 遍的、有空答案的。**直接拿它当答案去训，等于把这些毛病也一起教给模型。** 训练答案要用 `gold_fact`（标准答案）或人工审核过的版本。

## 3. 想要什么效果，就得配什么教材

这是最容易搞混的一点：**"干净"是手段，不是目的。**

干净 = 没有重复、没有空值、没有乱码、没有"标题和正文对不上"。

- 干净数据的作用是：**别把垃圾当教材，防止模型学坏。**
- 但干净数据**教不会模型"守规矩"**。

> 比方：你只教孩子"要好好说话"，从来没教过他"有人让他干坏事时该怎么拒绝"。那他真碰到的时候，要么愣住，要么就照做了。要想让他会拒绝，你必须专门给他看"有人这样问 → 我应该这样回"的示范。

| 你想要的             | 教材必须是什么                        | 方法                              |
| -------------------- | ------------------------------------- | --------------------------------- |
| 学本事（更专业）     | 干净的问答对                          | SFT（监督微调，照着示范学）        |
| 学规矩（更安全、会拒绝） | **坏问题 + 正确的拒绝 / 正确回答** | SFT，或偏好对比（DPO）             |
| 改掉某个具体说法     | 同一问题的"好答案 vs 坏答案"          | 偏好对比 / 知识编辑（本平台已有"定向抑制"） |

**一句话记住：干净数据防它学坏，示范数据教它学好。这是两件事，别指望一件顶两件。**

## 4. 本平台该选哪个动机

### 4.1 三个候选动机的对比

| 动机                       | 一句话说明                                           | 优点                                       | 问题                                                     |
| -------------------------- | ---------------------------------------------------- | ------------------------------------------ | -------------------------------------------------------- |
| A. 领域能力                | 用干净问答集微调，让模型在某领域答得更准             | 好理解、好实现                             | 太普通；与本平台"治理"主题关系弱；体现不出治理环节的价值  |
| **B. 治理价值证明（推荐）** | 治理前 / 治理后各训一次，同一张考卷对照，分数差即价值 | 直接服务平台主题；平台已有评估页承接；指标可量化 | 需要造两版数据集、跑两次训练                              |
| C. 安全退化观察（附加）    | 微调后领域能力上去了，安全护栏会不会被弄坏           | 贴合"内容安全"主题；有研究价值             | 需要额外准备一批"攻击性提问"当测试题                      |

### 4.2 推荐动机的标准写法（可直接抄进报告）

> **主动机**：本平台以同一底座模型、同一套超参数，分别使用"数据治理前"与"数据治理后"的数据集版本进行微调，并在固定测试集上对照评估，用量化差异证明数据治理环节对模型能力与安全性的实际影响。
>
> **附加观察**：记录微调前后模型安全表现的变化，观察领域微调是否造成安全对齐能力退化，并据此给出"微调时是否需要掺入安全数据"的结论。

### 4.3 为什么动机 B 才是本平台的正解

- **平台定位决定的。** 按《测试平台与各个课题的映射关系》，课题一负责"多源语料接入与治理、高质量语料库构建"，课题四负责"数据谱系、训练动态合规监控、全链路追溯"。本平台不是"造更强模型"的地方，而是"证明数据处理有用、并且全程可追溯"的地方。
- **平台已经把位置留好了。** 模型评估页已有"基线版本 vs 编辑后版本""风险减少率 = (基线风险数 − 编辑后风险数) / 基线风险数""示例保持率"这些口径——它们天生就是为对照实验设计的，不用另造一套。
- **实验的副产品就是课题四要的证据链。** 数据集版本 → 清洗任务 → 训练任务 → 模型版本 → 评估记录 → 调用 trace，这一条链正好是"全链路合规治理"要展示的东西。

## 5. 实验方案（可直接执行）

### 5.1 实验设计：A/B 对照

**固定项（三个模型必须完全一致）**：同一个底座模型（例如 `qwen3-4b-instruct`）、同一套超参数（学习率、批次、轮数）、同一张考卷（固定测试集）、同一套评测脚本。

**唯一变量**：训练数据集的版本。

| 编号 | 模型           | 训练数据              | 作用                       |
| ---- | -------------- | --------------------- | -------------------------- |
| M0   | 底座模型原样   | 不训练                | 基线，用来看"微调本身"的效果 |
| M1   | 底座 + LoRA    | v1.0.0（治理前，带异常） | 对照组                     |
| M2   | 底座 + LoRA    | v1.1.0（治理后，干净）   | 实验组                     |

**结论口径**：
- `M2 − M1` = **数据治理的价值**（本实验要的答案）
- `M1 − M0` / `M2 − M0` = 微调本身的效果

### 5.2 数据怎么切

1. **治理前数据集**：现有数据原样入库，打版本号（如 `v1.0.0`）。
2. **治理后数据集**：跑一遍清洗规则（去重、补空、字段归一、编码统一、日期归一），生成**新版本**（如 `v1.1.0`），原版本不动。
3. **切分**：训练 / 验证 / 测试三份。**测试集绝对不能出现在训练数据里**，否则分数虚高，实验作废。
4. **测试集要包含两类题**：能力题（领域问答）、安全题（诱导提问、越权请求、敏感话题）。
5. **测试集冻结版本**。一旦开跑就不能再改题，改了分数就不可比。

### 5.3 指标（建议全用，至少用前两组）

| 类别     | 指标                                   | 说明                                       |
| -------- | -------------------------------------- | ------------------------------------------ |
| 能力     | 事实正确率                             | 答案与标准答案一致的比例                   |
| 能力     | 格式合规率                             | 是否按要求的结构/长度作答                  |
| 能力     | 平均回答长度、重复率                   | 用来抓"啰嗦、复读"这类毛病                 |
| 安全     | 拒答率                                 | 面对不当请求时正确拒绝的比例               |
| 安全     | 风险命中数、风险减少率                 | 沿用评估页现有口径                         |
| 保持     | 示例保持率                             | 无关能力有没有被带坏                       |
| 代价     | 训练耗时、显存占用、产物体积           | 用于判断方案是否可推广                     |

### 5.4 结果记录表（模板）

| 模型 | 训练数据版本     | 能力正确率 | 风险命中数 | 拒答率 | 保持率 | 结论           |
| ---- | ---------------- | ---------- | ---------- | ------ | ------ | -------------- |
| M0   | 未训练           |            |            |        |        | 基线           |
| M1   | v1.0.0（治理前） |            |            |        |        | 待填           |
| M2   | v1.1.0（治理后） |            |            |        |        | 待填           |

### 5.5 三种可能结果，分别怎么写结论

- **M2 明显好于 M1**：治理有效，脏数据确实拖累了模型。这是最常见、也最想要的结论。
- **M2 ≈ M1**：当前这些异常类型并不影响模型效果。这同样是**有价值的负结论**——进一步要回答的是"到底哪类异常才真正有害"（例如重复样本、错误标签，往往比空值更伤模型）。
- **M2 比 M1 更差**：可能"洗过头了"，把有用的样本也删了。这本身就是对清洗规则的一次真实检验，要回头核对规则是否过严。

### 5.6 必须留下的证据（对应课题四的全链路追溯）

数据集版本 ID → 清洗任务 ID → 训练任务 ID → 基础模型 + LoRA 产物 → 超参数快照 → 评估记录 ID → 调用 trace ID。

缺任何一环，"治理有效"这句话就无法追溯，平台也就退化成"跑着玩"。

## 6. 具体怎么做：方法选型与门槛

### 6.1 三种做法对比

| 做法       | 大白话                     | 显存要求     | 产物大小 | 建议               |
| ---------- | -------------------------- | ------------ | -------- | ------------------ |
| 全量微调   | 把模型所有参数都改一遍     | 很高（几十 GB） | 完整模型 | 资源充足时考虑     |
| **LoRA**   | 给原模型打个"外挂补丁"，原模型不动 | 低（单卡可跑） | 几百 MB  | **推荐**           |
| QLoRA      | LoRA 的省显存版（底座先压缩） | 更低         | 几百 MB  | 显卡小的时候用     |

> 本项目 `docs/model-workbench-todo.md` 已要求模型管理区分"完整权重 / LoRA / QLoRA Adapter"，并记录基础模型版本与组合关系——选 LoRA 正好与既有设计对齐。

### 6.2 动手六步

1. **挑底座**：选一个本机或实验室服务器跑得动的开源小模型（现有数据就是用 `qwen3-4b-instruct` 等生成的）。
2. **造数据**：把问答表整成"问题 → 正确答案"，一行一条。答案用 `gold_fact` 或人工审核版本。
3. **选方式**：LoRA（见上表）。
4. **开训**：设学习率、批次、轮数（训练页表单已有这些字段），观察 loss 是否稳步下降。
5. **必做对照**：同一张考卷，M0 / M1 / M2 各考一次。**没有对照，就没有结论。**
6. **挂载调用**：把 LoRA 补丁绑到服务上，走部署页与调用页。

### 6.3 门槛的实话

- **数据量**：微调至少要几百条同类问答才看得出效果（建议 300～1000 条起）。
- 现状：`模型问答集_qa.csv` 共 40 条（不含表头），其中约 10 条是故意埋的坏样本，能直接用的只有 30 条上下——**不够训出效果，但足够跑通链路**。
- **好消息**：那些坏样本正是数据治理要清掉的东西，清完剩下的就是微调料。这就是"清洗前 vs 清洗后"的天然素材，不用另外编数据。

### 6.4 什么时候不用微调

- 只想让它"知道新知识" → 用 **RAG**，不用训练。
- 只在少数几个场景要特殊行为 → 先用提示词工程（写好系统提示）解决。
- **非微调不可的情况**：要改说话风格、输出格式、专业口吻、拒绝方式这类"习惯"。

## 8. 分阶段实施建议

- **P0 最小可行（先跑通）**：用现有 30 条可用问答，LoRA 微调一次，把"训练任务 → 模型版本 → 调用"整条链路走通，确认工具链可用。
- **P1 对照实验（本方案主体）**：扩到 300 条以上，造 v1.0.0 / v1.1.0 两个版本，训 M1 / M2，出对照表与结论。
- **P2 安全观察（加分项）**：补一批攻击性测试题，测微调前后的拒答率变化，回答"微调会不会弄坏安全护栏"。

## 9. 注意事项与坑

1. **别拿 `model_output` 当答案。** 它带着啰嗦、重复、跑题、空答案的毛病，会一起教给模型。
2. **测试集泄漏。** 测试题一旦进了训练数据，分数就不可信，实验直接作废。
3. **编码不统一。** `反例库_adversarial.csv` 是 GBK 编码，不是 UTF-8——这正是平台要治理的"编码异常"类型，入湖前先统一。
4. **只有推理接口的外部模型不能微调。** `docs/model-workbench-todo.md` 已要求：供应商只开放推理时，训练页应禁止把它选作可训练基础模型，并提示改用提示词 / RAG / 输入输出治理。
5. **"干净"≠"安全"。** 清洗解决"别学坏"，对齐解决"守规矩"，两码事。
6. **每次训练必须带版本号。** 数据集、超参、产物都要留版本，否则历史任务无法复现。
7. **别为了微调而微调。** 先用 RAG 和提示词试，确实解决不了再上微调。

## 附录 B：术语表（大白话对照）

| 术语         | 大白话解释                                                     |
| ------------ | -------------------------------------------------------------- |
| 预训练       | 读万卷书，学会说话和有常识                                     |
| 微调 / SFT   | 岗前培训，拿"问题 + 标准答案"的示范教它该怎么答                 |
| LoRA         | 给原模型打个外挂补丁，原模型不动，省显存、可随时摘掉            |
| QLoRA        | LoRA 的省显存版，先把底座压缩再挂补丁                          |
| DPO / 偏好对比 | 同一个问题给两个答案，告诉它哪个更好，纠正脾气                |
| RAG / 检索增强 | 不训练，把资料塞进提示词让它查着答                            |
| 过拟合       | 只会背题，换一道就不会                                         |
| 灾难性遗忘   | 学了新的，把旧的忘了                                           |
| 对齐退化     | 微调之后领域变强了，但变得不守规矩、更容易被套话               |
| 拒答率       | 面对不当请求时，模型正确拒绝的比例                             |
| 测试集泄漏   | 考试题混进了复习资料里，分数虚高、不算数                       |
